# Ticket P5.0 – Backend Route Extraction (Pure Modularization, Sequential)

## Phase
Phase 5 – Backend Route Extraction

## Objective
Extract all non-settings route groups from `routes/setup.js` into dedicated route modules while preserving *exact* runtime behavior (pure extraction, no refactors).

## Scope
Perform extraction sequentially in the following order (do not reorder):

1. **Auth** → create `routes/auth.js`
2. **Documents** → create `routes/documents.js`
3. **Chat & Playground** → create `routes/chat.js`
4. **History** → create `routes/history.js`
5. **Processing** → create `routes/processing.js`
6. **System** → create `routes/system.js`

For each group:
- Move only the route registrations and directly-required helpers for that group
- Maintain identical paths, middlewares, handlers, and exports
- Keep all existing side effects and initialization order equivalent
- After each group extraction:
  - Run server locally
  - Execute targeted smoke checks for that group (see validation checklist below)
  - Commit checkpoint (if using VCS) before proceeding to next group

## Validation Checklist (per extracted group)
- **Auth**
  - Login/logout functions as before
  - Session/JWT behavior unchanged
- **Documents**
  - Document viewing endpoints, thumbnails, PDFs behave identically
- **Chat**
  - Chat endpoints, streaming, playground endpoints behave identically
- **History**
  - Pagination/filters endpoints behave identically
- **Processing**
  - Scan/reset/pipeline endpoints behave identically
- **System**
  - Health/debug/webhook endpoints behave identically

## Constraints / Guardrails
- **Pure extraction only**: no behavior changes, no logic edits, no renames
- No API redesign
- No auth/permission model changes
- Preserve route registration order
- Preserve error handling and logging semantics
- Avoid cross-file circular imports; if unavoidable, mirror current require order and keep shared utilities in `setup.js` only if already present

## Deliverables
- New route modules:
  - `routes/auth.js`
  - `routes/documents.js`
  - `routes/chat.js`
  - `routes/history.js`
  - `routes/processing.js`
  - `routes/system.js`
- `routes/setup.js` reduced accordingly (but final cleanup is handled in P5.1)

## Acceptance Criteria
- Each extracted route group functions identically after extraction
- No route path changes (URLs identical)
- No regressions detected in targeted smoke checks after each step
