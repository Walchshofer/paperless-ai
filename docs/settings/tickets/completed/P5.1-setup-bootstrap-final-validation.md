# Ticket P5.1 – setup.js Bootstrap Cleanup + Full Regression Validation

## Phase
Phase 5 – Backend Route Extraction

## Objective
Finalize backend modularization by reducing `routes/setup.js` to bootstrap/shared middleware only and validating end-to-end stability across the application.

## Scope
- Update `server.js` (or equivalent entrypoint) to import and register route modules created in P5.0
- Reduce `routes/setup.js` to:
  - Shared middleware (only what is truly shared)
  - Route module registration wiring (imports and `router.use(...)` as needed)
  - Any unavoidable legacy bootstrap that cannot be moved without behavior change
- Ensure `routes/settings.js` remains consistent with prior phases (do not rework settings logic here)
- Execute **Flow 13: Backend Route Stability Validation** end-to-end:
  1. Authentication (login/logout)
  2. Document viewing & thumbnails
  3. Chat & streaming responses
  4. History pagination & filters
  5. Processing flows (scan/reset/pipelines)
  6. System health & webhooks/debug
  7. Settings save & reload

## Constraints / Guardrails
- No behavior changes (pure extraction)
- No refactors, renaming, reformatting-only changes beyond what is required to complete the move
- Preserve middleware ordering and error handlers
- If any shared helper is needed across modules, keep it in place (do not “improve” structure)

## Acceptance Criteria
- `routes/setup.js` is materially reduced (target per epic: ~300 lines)
- All routes behave identically post-extraction
- Flow 13 validation passes with no regressions
- Phase 5 considered complete and shippable
