# Ticket P1.x – Vitest Stabilization for UI Tests

## Phase
Phase 1 – Infrastructure & Foundation

## Objective
Stabilize Vitest test infrastructure to reliably run Preact + Radix UI tests in CI without picking up unrelated legacy Mocha test failures.

## Scope
- Add shallow Radix mocks for unit tests to avoid environment/hook mismatches
- Configure Preact transforms, JSDOM setup, and Vitest config to isolate Preact UI tests from legacy Mocha suites
- Split UI tests into a dedicated `test:ui` CI stage that runs only UI-related tests
- Ensure `shadcn-compat` test and future `src/ui/contracts` tests pass reliably in CI

## Background
From P0.0 shadcn compatibility testing, the Vitest run revealed:
- The `shadcn-compat` unit test passed after adding shallow Radix mocks
- Full Vitest suite picked up 96 failing legacy/Mocha-style tests (unrelated to UI work)
- Test environment issues with Preact hooks / JSDOM / transform configuration
- Need to isolate UI tests from legacy test suites to prevent CI noise

## Implementation Notes
1. **Shallow Radix Mocks**: Create mock implementations for Radix primitives that are sufficient for unit testing without requiring full DOM/hook environment
   - Example mocks for `@radix-ui/react-tabs`, `@radix-ui/react-label`, `@radix-ui/react-switch`, etc.
   - Place in `test/mocks/radix.js` or similar

2. **Vitest Configuration**: Update `vitest.config.ts` to:
   - Exclude legacy Mocha test files from Vitest discovery
   - Configure JSDOM environment properly for Preact
   - Set up proper transforms for TypeScript and JSX
   - Limit test file patterns to UI-specific paths (e.g., `src/islands/**/*.test.{ts,tsx}`, `src/ui/**/*.test.{ts,tsx}`)

3. **Test:UI Script**: Add npm script `test:ui` that:
   - Runs Vitest with UI-specific configuration
   - Uses appropriate file patterns to exclude legacy tests
   - Outputs clear test results for CI integration

4. **CI Integration**: Create separate CI stage `test:ui` that:
   - Runs `npm run test:ui`
   - Reports results independently from legacy Mocha test suite
   - Fails build only on UI test failures (not unrelated legacy failures)

## Constraints / Guardrails
- No changes to existing Mocha test suite or legacy test files
- No refactoring of existing tests outside UI scope
- Maintain backward compatibility with existing test infrastructure
- Short-term tactical remediation (accept test-splitting approach if needed)

## Acceptance Criteria
- [ ] Vitest run in CI shows `shadcn-compat` test passing reliably
- [ ] Vitest run does NOT pick up unrelated legacy test failures
- [ ] `npm run test:ui` script exists and runs only UI-related tests
- [ ] CI has dedicated `test:ui` stage that runs Preact + Radix UI tests
- [ ] Test output is clean (no spurious failures from legacy tests)
- [ ] Future `src/ui/contracts` tests can be added and will run in this pipeline

## Tasks
1. Create shallow Radix mocks in `test/mocks/radix.js`
2. Update `vitest.config.ts` to isolate UI tests:
   - Configure file patterns to include only UI test files
   - Exclude legacy Mocha test files
   - Configure JSDOM and Preact transforms properly
3. Add `test:ui` npm script to `package.json`
4. Test locally to ensure `shadcn-compat` test passes without legacy failures
5. Document test-splitting approach in `test/README.md` or similar
6. Add CI configuration for `test:ui` stage (separate ticket: CI job creation)
